# Мини-учёт оплат учебного центра

API учеников и оплат, запрос «должники за месяц» и веб-страница (вариант Б) для телефона.

**Стек:** Python, FastAPI, SQLAlchemy 2, Pydantic 2, SQLite. Тесты: pytest.

## Запуск с нуля

Нужен Python 3.12+ (проверено на 3.14). Docker и отдельная БД не нужны: SQLite-файл `data.db` и таблицы создаются автоматически при первом запуске.

**macOS / Linux**
```bash
git clone <repo-url> && cd <repo-dir>
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

**Windows (PowerShell)**
```powershell
git clone <repo-url>; cd <repo-dir>
python -m venv .venv
.venv\Scripts\Activate.ps1      # в cmd.exe: .venv\Scripts\activate.bat
pip install -r requirements.txt
uvicorn app.main:app --reload
```

После запуска:
- http://127.0.0.1:8000/ — веб-страница: должники и форма оплаты;
- http://127.0.0.1:8000/docs — Swagger UI, через него вызываются все методы API.

Если порт 8000 занят: `uvicorn app.main:app --reload --port 8001`.

**Тесты** (с активированным `.venv`):
```bash
pytest
```
Тесты используют in-memory SQLite и не трогают `data.db`.

Другой путь к базе можно задать через переменную `DATABASE_URL` (по умолчанию `sqlite:///data.db`).

## Как пользоваться

**Учеников добавляют и редактируют через `/docs`.** На веб-странице формы для учеников нет, там только список должников и добавление оплаты (как и требует вариант Б). Группа — обычное текстовое поле ученика, создавать её отдельно не нужно: достаточно указать `group` при создании ученика.

Быстрый пример через curl:
```bash
curl -X POST localhost:8000/students -H 'Content-Type: application/json' \
  -d '{"name":"Али Валиев","phone":"+998 90 123-45-67","group":"Python-1","monthly_fee":"500000"}'

curl -X POST localhost:8000/payments -H 'Content-Type: application/json' \
  -d '{"student_id":1,"amount":"200000","paid_on":"2026-10-05"}'

curl 'localhost:8000/debtors?month=2026-10'
```

### API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/students` | Создать ученика: `name`, `phone`, `group`, `monthly_fee` |
| `GET` | `/students` | Список учеников, фильтр `?group=` |
| `GET` | `/students/{id}` | Один ученик |
| `PATCH` | `/students/{id}` | Частичное изменение |
| `DELETE` | `/students/{id}` | Удаление (мягкое, см. ниже) |
| `POST` | `/payments` | Добавить оплату: `student_id`, `amount`, `paid_on` (необязательно, по умолчанию сегодня) |
| `GET` | `/students/{id}/payments` | Оплаты ученика по дате |
| `GET` | `/debtors?month=YYYY-MM` | Должники за месяц: `paid`, `debt` для каждого; без `month` берётся текущий месяц |

Коды ошибок: `404` — ученик не найден или удалён, `422` — ошибка валидации.

## Решения и допущения

В ТЗ ряд вещей не уточнён, ниже — как я их трактовал.

| Вопрос | Решение |
|---|---|
| Долг за месяц | `debt = monthly_fee − сумма оплат за [1-е число месяца; 1-е число следующего)`. В список попадают ученики, у которых `debt > 0`. Отсортировано по долгу (больше → меньше) |
| Ученик без оплат | Тоже должник, долг = полная месячная сумма |
| Переплата / долг прошлых месяцев | Не переносятся: каждый месяц считается отдельно. Переплатил — в этом месяце не должник, в следующем снова должен всю сумму |
| Дата создания ученика | Не учитывается: ученик, добавленный в ноябре, будет должником и за октябрь, если за октябрь нет оплат |
| Изменение месячной суммы | **Пересчитывает и прошлые месяцы**: истории цен нет, всегда берётся текущая `monthly_fee` |
| Группа | Текстовое поле ученика, без отдельной таблицы |
| Деньги | `Decimal`, колонка `Numeric(12, 2)`, в JSON — строка (`"500000.00"`). Суммы > 0, не больше 2 знаков после точки |
| Дата оплаты | Тип `DATE` без времени. «Сегодня» и «текущий месяц» считаются по **Asia/Tashkent**, чтобы оплата 31-го числа в 23:30 не уехала в другой месяц из-за UTC. Дата в будущем — `422` |
| Удаление ученика | Мягкое (`deleted_at`): ученик пропадает из списка, из должников и из API (`404`), но его оплаты остаются в базе |
| Телефон | Пробелы, `-`, `(`, `)` удаляются; остаток должен совпадать с `+?` и 7–15 цифр. Хранится очищенным. Уникальность не проверяется (у братьев и сестёр может быть один номер родителя) |
| Интерфейс | Вариант Б: одна страница на чистом HTML/CSS/JS, отдаётся тем же FastAPI. Нажатие на карточку должника выбирает ученика в форме и подставляет сумму долга |

### Почему суммы складываются в Python, а не в SQL

В SQLite нет настоящего десятичного типа: SQLAlchemy хранит `Numeric` как `REAL` (float). Если считать `SUM(amount)` и сравнивать с `monthly_fee` прямо в SQL, появляются ошибки округления. Например, `0.70 + 0.10` даёт `0.7999999999999999 < 0.80`, и ученик, оплативший всё полностью, попадает в должники.

Поэтому SQL только выбирает строки (активных учеников и их оплаты за месяц), а сумма и сравнение `paid < monthly_fee` считаются в Python через `Decimal`. При чтении каждое значение округляется до 2 знаков, это безопасно: суммы с точностью до копеек хранятся в float без потерь. Тест `test_decimal_precision_070_plus_010` показывает, что SQL-вариант ошибся бы, а API отвечает верно. При переходе на PostgreSQL (`NUMERIC`) суммирование можно вернуть в SQL.
